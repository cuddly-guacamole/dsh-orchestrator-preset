# ADR: 规则按「决策时刻是否必须生效」分三层 —— 常驻只放触发/判定句，SKILL 放形制，`tools/` 放能判对错的形状

状态：已采纳（2026-10-27，按一次审计 REJECT 的 8 条 findings 重排**已落盘但未提交**的三条机制；本轮只重排落点、并给其中可机械化的一半补上断言，不新增规则语义）

## 背景

三条机制上一轮的落点是按「哪里顺手」而不是按「决策时刻是否必须生效」定的，三处都露了：

- `skills/orch-evidence-protocol/SKILL.md` 的 §二（路径审计四分类）表后追加了 `frozen` 一句，**没有报错形状**；
- 同一文件 §三之二（同一 lane 续轮复用）**末尾**追加了「finding 只有两种合法终局」与「类升级与收敛上界」两段 —— 与 lane 续轮无关的规则贴在续轮小节尾部（结构错位）；
- `personas/orchestrator.minimal.md` 里塞了一句中英混排的整句（上一轮在 :57，本轮已换成英文单句），把「frozen + 两种终局 + 升级台阶」压成一行，读起来像补丁。

三条规则是否**在需要它的那一刻进上下文**，取决于承载文件的装配时机，这是可读源码的既有事实，不是偏好：

| 事实 | 位置 |
|---|---|
| SKILL 正文在加载期**不被复制**，原生 skill 工具未被改动 ⇒ SKILL 只在主动调 `skill` 时进上下文 | `extensions/dsh/index.js:6-8` |
| persona prefix 作为常驻 systemPrompt section **每回合装配** | `plan-aware-persona.mjs:98-102` |
| 常驻 routing 段同样每回合装配 | `routing-sections.mjs:194-203` |

⇒ **每回合都付费的文本，只该放「不查文档也会错」的那一句**；形制（报错形状、notepad 写法、升级台阶）可以留给被调用时才进上下文的 SKILL；能被程序判对错的部分，放 `tools/`。

## 决定

按「决策时刻是否必须生效」分三层，放错层的判据也一并定：

| 层 | 放什么 | 放错怎么看出来 |
|---|---|---|
| **常驻**（`personas/*.md`） | 触发/判定句：一句话说清「什么条件触发、结论是什么」。两档同改、英文、≤1 句 | 删掉它 ⇒ 该情形无人知道要触发；加长它 ⇒ 每回合都在付费 |
| **SKILL**（`skills/*/SKILL.md`） | 形制与怎么做：报错形状、notepad 写法、判据细节、升级台阶 | 它只在主动调 `skill` 时进上下文 ⇒ 不能承载「不查也会错」的判定句 |
| **`tools/`** | 能被程序判对错的形状：入参、退出码、false/null 语义 | 跑不出 0/1/3 三态 ⇒ 它还是散文，只是换了扩展名 |

本轮落点（三条机制的重排结果）：

1. **常驻句**（两份 persona 各 1 句、英文）：`frozen` 的触发条件 + `AUDITED-BY: <path>` 的指针义务 —— `personas/orchestrator.md:118`（**独立一段**，不再追加在长段末尾）、`personas/orchestrator.minimal.md:57`。判定形制（另一份档的末行恰为 `RESULT: PASS`）属形制、不下沉到常驻，留在 §七。
2. **SKILL §七「审查门」**（独立小节，`SKILL.md:94`，正文自 :96 起）：`frozen` 完整判据 + 报错形状 `frozen <path>: <auditor evidence file>` + 指针写入契约 + finding 两种终局 + 类升级台阶。§二只留一行指针（`frozen` → §七），分类语义与判据细节分居两节。
3. **断言层**：`tools/check-frozen-audit.mjs` + `npm run verify:frozen-audit`。入参一个证据档，退出码 **0 通过 / 1 真失败 / 3 无 frozen 路径（未适用）**，false 优先于 null。脚本与解析器（`tools/lib/evidence-parse.mjs`）已由 `.gitignore` re-admit ⇒ **clone 侧有、npm 侧没有**（`files[]` 不动，发布面不变）。
4. **只把可机械化的一半做成断言**：三条机制里只有 `frozen` 的指针部分能被程序判对错；finding 两种终局与类升级台阶本身不可断言 ⇒ 留在 SKILL 散文层，不假装成断言（§七 已写明「不可断言 ⇒ notepad 显式写为何不可断言」）。

## 考虑过的选项

1. **三条都常驻**（每份 persona 各加 2–3 句）。被否：常驻文本每回合付费；且 finding 终局与升级台阶在常驻层没有触发点 —— 它们回答的是「审完之后怎么收尾」，不是「这一回合要不要触发」。
2. **三条都只留在 SKILL**。被否：SKILL 只在主动调用时进上下文（`extensions/dsh/index.js:6-8`）⇒ 一个没想到要调 skill 的回合，`frozen` 门根本不会触发；而 `frozen` 恰恰属于「不查文档也会错」的那一类。
3. **`frozen` 做成纯断言，常驻层一个字不写**。被否：脚本要有人跑。触发句是断言被调用的唯一入口 ⇒ 常驻层保留 1 句，断言层负责判对错；两者少一个就退化。
4. **保留 minimal 里那句中英混排整句，只补报错形状**。被否：「整句」既超了常驻层的粒度上限，又让两份 persona 不同形（full 档是英文散句、minimal 是混排整句），使「两档同改」不可核对。

## 后果

- **常驻层只剩一句，判断力由断言层兜住。** 句子本身不可执行；`verify:frozen-audit` 才判对错。缺句子 ⇒ 没人跑脚本；缺脚本 ⇒ 句子靠自觉。这条互相依赖是本决定的**主要代价**，写在这里以免下一轮把它读成多余的一层。
- **§二 现在只有一行指针。** 指针是刻意的：分类语义留在 §二表里，判据细节在 §七，避免同一段判据两处漂移。代价是读 §二的人要跳一次。
- **本轮移出常驻的只是 finding 类升级台阶；lane 升级梯仍留在两份 persona，本轮未动。** finding 类升级讲的是「审完之后同一类 finding 再次出现怎么办」，触发点在收尾而不是每回合，所以归 SKILL §七。lane 升级梯（`personas/orchestrator.md:138`、`personas/orchestrator.minimal.md:78`：重试一次 ⇒ 换角度 ⇒ 指出具名理由才换实例）是**每回合都可能用到**的故障处置，按本准则本就该常驻，因此**本轮未动**。上一轮它在 `Lane ended abnormally` 行尾，本轮也没有把它挪走。两档同改是分层准则的一部分，不是漏改。
- **`personas/auditor.md:72` 改成「协调者写指针」的形状。** 该 lane 的工具面是 `['read','read_image','glob','grep']`（`tools/preset-declaration.mjs:603`；`:580` 是 `lanePresetId` 的定义），**没有写工具**，所以旧文「它的唯一书面产物是本任务的证据档」不可实现；现在写明：判定作为该 lane 的回报存在，协调者把它转写进证据档并落 `AUDITED-BY:` 指针。若不改这一行，`frozen` 门会永远等一份**永远不会出现**的审计档 —— 机制当场不可实现。
- **断言层用的是既有先例的语义，不是新发明**：`tools/audit-personas.mjs` 早已是 0/1/3 + false 优先于 null，本 ADR 只是把同一语义用到 `frozen` 上，两个脚本的退出码可以对着读。
- **`node tools/gen-cordis-patch.mjs --check` 仍须为 0**：本决定只动 persona / SKILL / `tools/` / `package.json` 的 `scripts`，不动 `cordis.patch.yml`（生成物，禁止手改），也不动 `npm test` 的组成。

## 已记录的不对称

- **`SKILL.md:72`「禁止轮询」按本准则应当常驻，而 `orchestrator.minimal.md` 没有这一句。** 它是判定句（「列举工具不是 poll 工具 ⇒ 等结果时结束回复」），属于「不查文档也会错」那一类，本应在两份 persona 里各占一行。本轮**只记录，不实现**：本轮的重排边界是「上一轮那三条机制」，混入第四条会让 V8 的文件面与每份 persona 的净增上限都不可核对；且常驻每份 persona 的净增已各用满到上限。要修它需要单独一轮（两份 persona 同改 + 一句英文 ≤1 行 + 一条复跑判据）。
- **`SKILL.md` 的 finding 终局与类升级台阶仍不可断言。** 本轮没有把它们做成脚本，这是有意的选择而不是遗漏：它们的触发点分布在对话里，没有可判对的入参。若同类 finding **第三次**出现，按 §七 上界改规则文本，而不是再加一段散文。
- **断言只覆盖「指针合格」，不覆盖「审查质量」**：`AUDITED-BY` 末行为 `RESULT: PASS` 能让门打开，但不保证那次审查真的读了改动。这是本层的已知残余，`frozen` 门不能替代审查本身。
- **已提交的 frozen 改动用默认 `--base HEAD` 读 `3`。** 适用性来自 `git status --porcelain` ∪ `git diff --name-only <base>`，默认 base 是 `HEAD` ⇒ 改动一旦提交，工作区干净，交集为空，门读到「不适用」。`3` 不是放行（§七 已写明），但这**确实是一个漏判方向**，不是「只会更严」：要覆盖已提交的改动，必须显式传 `--base HEAD~1`。这是「默认值服务于未提交的完成声明」这个选择的代价，写在这里免得把 `3` 读成绿灯。

## 已知的过近似（两处）

1. **门按整棵树判适用，并把本档自述的 frozen 路径并入。** `check-frozen-audit.mjs` 的适用性来自两处：① `git status --porcelain` ∪ `git diff --name-only <base>` 与三个 frozen glob 求交；② **本档路径审计小节里声明的 frozen 路径**（`in_scope personas/x.md` 这类行，围栏之外）。只要**工作区**里有未提交的 frozen 改动，它就把**每一份**被指向的证据档都判成适用，包括「审查档自己」那份。这是**假阳性方向**：规则义务只落在「宣称改动完成」的那一份档上，其余档并不欠 `AUDITED-BY:`。代价是一份无关档也会读到 `1`；不这样做的代价是「删掉路径审计小节 / 换个仓」就能绕过门，那更糟。而 ② 那一半只能让门**更严**：声明一条 frozen 路径不会让门变松，只会在 git 看不见（仓外 / 未跟踪）时把门拉严。⇒ 见到无关档读 `1`，先看工作区是否有未提交的 frozen 改动，不要把 `1` 读成那份档的缺陷。
2. **五 kind 之外的围栏写法静默按现有规则解析。** 闭集（`mixed-length` / `unclosed` / `mixed-char` / `indented` / `long-run`）之外没有第三个答案：脚本不报歧义，照现有规则往下解析。方向同样更严（歧义 ⇒ `1`），但**没覆盖到的写法不会被指出来** —— 「解析器没说话」不等于「这份档的围栏没问题」。遇到新写法按 §七 的类升级上界处理（同一类第三次出现 ⇒ 改规则文本，而不是再加一段散文）。

## 推翻条件

- **冻结改动占多数会话、SKILL 触发率趋近 100% 时，仍然选断言层，因为它能 fail。** 那种情形会削弱「SKILL 省上下文」的理由（反正每回合都调），但不削弱断言层的理由：断言的价值不是省 token，而是「能给出 1」。只有 `check-frozen-audit.mjs` 这一类断言失去鉴伪力（恒为 0，或者反过来连正例都过不了），才回到这张表重开分层。
- 另两条会真正推翻本 ADR 的情形：DSH 给 SKILL 一种常驻语义（`alwaysApply` 或等价机制）⇒ 第二层的「不进上下文」前提消失，形制可以下移到 SKILL 而不丢触发；或 persona 的装配不再每回合发生 ⇒ 第一层的成本模型改变。
